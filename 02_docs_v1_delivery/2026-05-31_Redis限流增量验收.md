# 2026-05-31 Redis 限流增量验收

## 本轮目标

在已上线的 Webhook、SSE 流式对话、内存 API 限流基础上，继续补齐多实例部署需要的 Redis 可选限流能力。

本轮按用户要求只做本地开发和本地验证，暂不做服务器部署验证。

## 后端变更

- 新增可配置限流后端：
  - `RATE_LIMIT_BACKEND=memory`：默认内存限流，保持原有行为。
  - `RATE_LIMIT_BACKEND=redis`：使用 Redis 固定窗口限流，适合多实例部署。
- 新增限流阈值配置：
  - `RATE_LIMIT_WINDOW_SECONDS`：固定窗口长度，默认 60 秒。
  - `RATE_LIMIT_TENANT_PER_MINUTE`：同一租户默认每分钟 120 次。
  - `RATE_LIMIT_USER_PER_MINUTE`：同一用户默认每分钟 60 次。
  - `RATE_LIMIT_AUTH_IP_PER_MINUTE`：登录/注册同一 IP 默认每分钟 20 次。
- Redis 限流实现使用 `INCR` 和 `EXPIRE`，Key 前缀为 `mu:{APP_ENV}:rate:global:`。
- Redis 请求设置短超时，避免 Redis 异常时长时间阻塞业务请求。
- Redis 计数异常时自动回退到内存限流，避免 Redis 短时不可用导致 API 整体不可用。
- 触发限流时继续返回统一响应结构，HTTP 状态码为 `429`，中文错误信息为“请求过于频繁，请稍后再试”。
