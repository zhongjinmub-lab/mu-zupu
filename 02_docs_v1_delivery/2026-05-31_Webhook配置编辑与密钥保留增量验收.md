# Webhook 配置编辑与密钥保留增量验收

## 本轮目标

修复 Webhook 配置更新时未传 `secret` 会清空原签名密钥的问题，并在管理台补齐 Webhook 编辑入口。

## 后端变更

- `PUT /webhooks/{webhook_id}` 在未传 `secret` 或 `secret` 为空字符串时保留原签名密钥。
- Webhook 启用/停用只更新状态，不再误清空签名密钥。
- 名称、接收地址、状态和事件列表继续沿用原有的局部更新语义。

## 前端变更

- Webhook 列表新增“编辑”按钮。
- 点击“编辑”后，表单会载入名称、接收地址、订阅事件和状态。
- 签名密钥输入框不会展示已有密钥原文。
- 编辑保存时，如果密钥输入框留空，则保留原密钥；填写新密钥时才替换。
- 表单新增“取消编辑”按钮，可恢复创建模式。

## 验收步骤

1. 创建一个带签名密钥的 Webhook。
2. 点击该 Webhook 的“停用”或“启用”，确认配置仍可测试发送。
3. 点击“编辑”，修改名称或订阅事件，签名密钥留空并保存。
4. 再次执行测试发送，确认签名密钥没有被清空。
5. 点击“编辑”，填写新的签名密钥并保存，确认后续投递使用新密钥。

## 验证命令

- 前端语法检查：`D:\Node.js\node.exe --check 02_frontend\assets\app.js`
- 后端测试：在 `01_backend` 目录执行 `go test ./...`
- 差异检查：`git diff --check`

## 注意事项

- 本轮不改接口响应结构，仍保持与现有管理台兼容。
- 管理台不展示黑色 JSON 原文区域，新增提示均使用中文摘要。
- 本轮不部署服务器，部署验证留到后续明确要求时执行。
