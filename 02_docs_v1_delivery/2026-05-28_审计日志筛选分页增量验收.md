## 接口能力

`GET /api/v1/audit-logs` 继续要求：

- `Authorization: Bearer <token>`
- `X-Tenant-ID: <tenant_id>`

新增或增强查询参数：

| 参数 | 说明 |
|---|---|
| `action` | 按审计动作筛选，例如 `http.post`、`tenant.invitation.create` |
| `resource_type` | 按资源类型筛选，例如 `http_request`、`tenant_invitation` |
| `actor_user_id` | 按操作者用户 UUID 筛选 |
| `from` | 起始时间，支持 RFC3339/RFC3339Nano 或 `YYYY-MM-DD` |
| `to` | 结束时间，支持 RFC3339/RFC3339Nano 或 `YYYY-MM-DD` |
| `limit` | 每页数量，默认 50，最大 100 |
| `cursor` | 下一页游标，由上一页 `next_cursor` 返回 |

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [],
    "next_cursor": ""
  },
  "request_id": "trace-id"
}
```

## 隔离与安全

- 查询固定以当前 `X-Tenant-ID` 解析出的租户上下文为边界，不接受客户端传入 `tenant_id` 覆盖。
- `actor_user_id` 必须是合法 UUID。
- `from > to` 会返回参数错误。
- `cursor` 为服务端生成的 URL 安全 base64，不包含密钥、token 或请求 body。
- 分页排序使用 `created_at DESC, id DESC`，避免同一时间戳下翻页重复或遗漏。
