# 2026-05-31 Webhook 投递记录筛选增量验收

## 本轮目标

在已完成 Webhook 配置、测试发送、投递记录和失败重试 Worker 的基础上，补充管理台排障能力：按 Webhook、事件类型、投递状态筛选投递记录。

本轮按用户要求只做本地开发和本地验证，暂不做服务器部署验证。

## 后端变更

- `GET /api/v1/webhook-deliveries` 新增筛选参数：
  - `endpoint_id`：按 Webhook 配置筛选，要求合法 UUID。
  - `event_type`：按事件类型筛选。
  - `status`：按投递状态筛选，支持 `success`、`failed`。
  - `limit`：返回数量，默认 50，最大 200。
- 新增 `DeliveryQuery` 统一处理参数归一化和校验。
- 仓储层使用参数化 SQL 动态追加筛选条件，继续保持 `tenant_id` 隔离。
- 查询参数错误时返回 `400`，避免无效 `endpoint_id` 变成数据库错误。

## 前端变更

- Webhook 页面投递记录区新增筛选栏：
  - Webhook 配置。
  - 事件类型。
  - 投递状态。
  - 返回数量。
- “筛选”“刷新”会按当前筛选条件请求投递记录。
- “重置”恢复全部记录、默认 50 条。
- 投递记录继续使用中文摘要展示，没有新增黑色 JSON 原文区域。

## 单元测试

- Webhook service 测试新增 `DeliveryQuery` 覆盖：
  - 空格裁剪。
  - 事件类型和状态归一化。
  - 超限 `limit` 回落默认值。
  - 非法状态和非法 `endpoint_id` 校验。
