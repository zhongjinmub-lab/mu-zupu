# Webhook 签名密钥响应脱敏增量验收

## 本轮目标

避免 Webhook 签名密钥通过接口响应返回给前端，同时保留测试发送、正式投递和重试 Worker 的签名能力。

## 后端变更

- Webhook 配置响应不再返回 `secret` 原文。
- Webhook 配置响应新增 `has_secret` 字段，用于表示是否已配置签名密钥。
- 内部投递流程仍从数据库读取真实密钥，用于生成 `X-Webhook-Signature`。
- 创建、编辑、列表接口均使用同一脱敏结构。

## 前端变更

- Webhook 编辑表单改为读取 `has_secret` 判断是否已有密钥。
- 密钥输入框始终为空，不展示已有密钥原文。
- 留空保存仍保留原密钥，填写新值时替换密钥。

## 验收步骤

1. 创建一个带签名密钥的 Webhook。
2. 刷新 Webhook 列表，确认接口响应和页面状态中不展示 `secret` 原文。
3. 确认该 Webhook 返回 `has_secret: true`。
4. 点击“编辑”，确认密钥输入框为空，并提示“留空则保留原密钥”。
5. 留空保存后执行测试发送，确认签名投递仍可用。
6. 创建不带密钥的 Webhook，确认返回 `has_secret: false`。

## 验证命令

- 后端测试：在 `01_backend` 目录执行 `go test ./...`
- 差异检查：`git diff --check`

## 注意事项

- 本轮不改变数据库结构。
- 本轮不部署服务器，部署验证留到后续明确要求时执行。
- 管理台继续使用中文摘要，不新增黑色 JSON 原文展示区。
