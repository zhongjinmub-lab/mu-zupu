# 2026-05-31 生产配置归档恢复脚本增量验收

## 目标

在 `backup.sh` 已归档前端、Nginx、systemd 和运行配置之后，补齐配置归档恢复脚本，形成数据库恢复和运行文件恢复两条独立、可控的恢复路径。

## 变更

- 新增 `01_backend/deploy/production/scripts/restore-config.sh`。
- 默认读取最新 `mu_agent_saas_config_*.tar.gz`，也可通过 `CONFIG_BACKUP` 或命令行参数指定。
- 必须显式设置 `CONFIRM_CONFIG_RESTORE=yes` 才会恢复。
- 恢复前会再次调用 `backup.sh` 备份当前现场。
- 恢复范围：
  - `docker-compose.yml`
  - `mu-agent-saas.env`
  - `migrations`
  - `scripts`
  - `frontend`
  - `nginx`
  - `systemd`
- 恢复后执行 `systemctl daemon-reload`，启动服务并调用 `smoke.sh`。
- Linux/Windows 发布脚本已校验 `restore-config.sh` 进入发布包。
- 单元测试覆盖配置恢复脚本关键步骤。

## 验收

- [x] 配置恢复必须显式确认。
- [x] 配置恢复前自动备份当前现场。
- [x] 配置恢复覆盖前端静态文件、Nginx 和 systemd 模板。
- [x] 配置恢复后执行冒烟检查。
- [x] 发布包校验包含 `restore-config.sh`。
- [x] 本轮不部署服务器，部署验证留到后续明确要求时执行。
