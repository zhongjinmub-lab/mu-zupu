# 2026-05-31 增量验收:真实第三方支付渠道接入(支付宝 + 可插拔渠道抽象)

## 背景

支付能力此前仅支持 mock 渠道(`only mock payment channel is supported in MVP`)。本次新增可插拔支付渠道抽象层,并接入支付宝电脑网站支付(`alipay.trade.page.pay`)作为首个真实渠道,同时保留 mock 渠道的开发体验与既有回调入账逻辑不变。

## 后端

- [x] 新增 `internal/payment` 包(纯标准库实现,便于独立单测):`Provider` 接口、`Registry`、`BuildRegistry`。
- [x] `MockProvider` 保留 JSON + HMAC-SHA256(`X-Payment-Signature`)回调语义。
- [x] `AlipayProvider` 实现:`CreatePrepay` 本地构造并 RSA2 签名跳转 URL(不发起网络请求);`VerifyNotify` 解析 `application/x-www-form-urlencoded` 异步通知并用支付宝公钥 RSA2 验签。
- [x] 支付宝 `trade_status` 映射:`TRADE_SUCCESS`/`TRADE_FINISHED` 记为已支付,`TRADE_CLOSED` 记为失败,中间态不更新支付单。
- [x] `config` 新增渠道与凭据配置:`PAYMENT_CHANNELS`、`PAYMENT_NOTIFY_BASE_URL`、`PAYMENT_RETURN_URL`、`ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY`、`ALIPAY_PUBLIC_KEY`、`ALIPAY_GATEWAY`、`ALIPAY_SIGN_TYPE`。
- [x] `POST /payment-orders` 支持按启用渠道校验,创建支付单后调用渠道生成 `prepay`(`pay_url` 等)并随响应返回,同时把非敏感预支付摘要写入支付单 `callback_payload.prepay`。
- [x] 新增公开端点 `POST /api/v1/payment-notify/{channel}`(无需 JWT/租户上下文):由渠道做原生验签,按 `pay_no` 反查租户后复用既有入账逻辑,支付成功触发 `order.paid` Webhook。
- [x] 公开通知端点路径与租户作用域 `/payments/{payment_id}/...` 不冲突(独立首段,避免 gin 路由通配符冲突)。
- [x] 渠道凭据仅通过环境变量注入,日志与持久化不保存敏感明文;预支付摘要仅保留渠道、方式、跳转地址和提示。

## 前端

- [x] 订单列表新增支付渠道选择(mock / 支付宝)。
- [x] 创建支付单后,若返回 `prepay.pay_url` 则在新窗口跳转第三方渠道完成支付;mock 渠道保留自动回调演示。
- [x] 支付动作结束后刷新订单、支付单、回调审计与订阅信息。
