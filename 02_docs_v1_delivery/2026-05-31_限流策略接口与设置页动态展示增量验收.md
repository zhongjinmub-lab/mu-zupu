# 2026-05-31 限流策略接口与设置页动态展示增量验收

## 本轮目标

在已完成内存/Redis API 限流能力基础上，补齐管理台对真实限流策略的只读展示能力，避免设置页继续硬编码默认文案。

本轮继续只做本地主线开发，不执行服务器部署验证，不读取服务器信息文件。

## 后端变更

- 新增 `settings` 模块。
- 新增接口：`GET /api/v1/settings/rate-limit`。
- 接口返回当前后端配置中生效的限流策略摘要：
  - 限流后端：`memory` 或 `redis`。
  - 窗口长度：`window_seconds`。
  - 租户窗口阈值：`tenant_per_window`。
  - 用户窗口阈值：`user_per_window`。
  - 登录注册 IP 窗口阈值：`auth_ip_per_window`。
  - Redis 是否启用：`redis_enabled`。
  - 中文故障策略说明：`redis_fallback_label`。
- 接口挂在登录用户路由下，不强制租户上下文，因为该策略是全局运行配置摘要。
- 接口不返回 Redis 地址、Redis 密码、数据库连接串、JWT 密钥等任何敏感信息。

## 前端变更

- 设置页“API 限流策略”从静态硬编码改为调用后端接口动态展示。
- 页面展示中文摘要卡片：
  - 租户 API 限流。
  - 用户 API 限流。
  - 登录注册 IP 限流。
  - 限流后端状态。
  - 故障回退策略。
- 增加“刷新”按钮，可单独刷新限流策略。
- 加载失败时展示中文错误摘要，不展示黑色 JSON 原文区域。

## 验收要点

- 登录后全局刷新会自动加载限流策略。
- 设置页点击“刷新”会重新请求 `/settings/rate-limit`。
- 配置为 `RATE_LIMIT_BACKEND=redis` 时，接口只返回 `backend=redis` 和 `redis_enabled=true`，不暴露 Redis 连接信息。
- 配置为空或非 `redis` 时，接口按 `memory` 返回，符合当前实际限流初始化逻辑。
