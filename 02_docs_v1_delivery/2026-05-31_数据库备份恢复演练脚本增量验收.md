## 恢复演练流程

`restore-drill.sh` 用于日常演练，默认读取最新 `mu_agent_saas_*.sql.gz` 备份，也可以通过 `DB_BACKUP` 指定备份文件。

执行顺序：

1. 创建临时演练库 `mu_agent_saas_restore_drill`。
2. 将 gzip SQL 备份恢复到演练库。
3. 查询 `schema_migrations`，确认恢复后的迁移记录可读且数量大于 0。
4. 校验租户、用户、智能体、知识库、对话、审计、订阅、支付、授权、Webhook 和族谱关系等核心业务表存在。
5. 默认删除演练库，避免占用生产资源。
6. 如需人工检查，可设置 `KEEP_DRILL_DB=yes` 保留演练库。

## 真实恢复流程

`restore.sh` 用于生产真实恢复，必须显式设置 `CONFIRM_RESTORE=yes`。

执行顺序：

1. 真实恢复前再次调用 `backup.sh` 备份当前现场。
2. 停止 API、文档 Worker、Webhook Worker。
3. 终止目标库连接。
4. 删除并重建目标库。
5. 从指定 gzip SQL 备份恢复。
6. 重启服务并调用 `smoke.sh` 验证。
